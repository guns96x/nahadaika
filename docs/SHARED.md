# Хмара й спільні чати: налаштування Firebase

Хмара й спільні чати працюють лише у варіанті `github` і лише коли налаштовано проєкт Firebase. Без налаштувань пункти «Поділитися з рідними» та «Зберігати в хмарі» не з'являються, а решта застосунку працює як раніше.

Головні дані лишаються на телефоні (будильники, віджет, робота без інтернету). Firebase зберігає копію й роздає зміни:

- **Зберігати в хмарі** (Налаштування → Хмара): вхід через Google, і всі чати дзеркаляться в хмару. На новому телефоні після входу тим самим акаунтом чати повертаються. Анонімний вхід прив'язується до Google-акаунта, тож уже спільні чати не губляться.
- **Спільні чати**: працюють і без хмари, на анонімному вході.

## Що синхронізується

- Текстові нагадування: текст, час, повтор, будильник, «Готово», видалення.
- Обговорення під нагадуваннями з іменем автора.
- Голосові, відеокружечки й фото в **спільних** чатах. Без Storage (план Spark) їх везе «кур'єр» через Firestore (див. нижче). Якщо підключено Storage (`firebase.storageBucket`), медіа йде туди й зберігається постійно. В особистих копіях у хмарі медіа без Storage лишається на телефоні.

Будильник ставить кожен телефон сам. Старі нагадування з історії чату в нового учасника не дзвонять. Повторюване нагадування переходить на найближчий раз.

Коли застосунок відкрито, зміни підтягуються одразу (слухач Firestore). Коли закрито — **миттєве push-сповіщення** (FCM через сервер на Supabase, див. нижче): телефон прокидається, забирає зміни чату й показує сповіщення «Оля: купити хліб». Запасний шлях — фоновий `SharedSyncWorker` раз на 2 години (якщо сервер сповіщень заснув чи FCM не дійшло).

## Медіа «кур'єром» (без Storage)

- Перед відправкою: фото — до 1600 px JPEG (~300 КБ), відео більше 4 МБ — до 540p ~1,5 Мбіт/с (Media3 Transformer). Голосові — як є. Оригінал у автора не змінюється. Що й після стиснення більше 25 МБ — лишається лише в автора.
- Файл ріжеться на шматки до 900 КБ: `chats/{чат}/media/{нагадування.ext}` (опис: розмір, SHA-256, хто вже отримав) і поруч `.../media/{нагадування.ext}~{0..31}`. Шматки лежать не в підколекції, бо мають власний `expireAt`: прибирання знайде навіть ті, чий опис зник. Читають і пишуть лише учасники чату (`firebase/firestore.rules`, перевірки — `tools/firebase_rules_test.py`).
- Отримувач перевіряє розмір і SHA-256 і позначає себе в `receivedBy`. Коли файл мають усі інші учасники, останній отримувач видаляє його з хмари. Отже, хто приєднався пізніше, старі медіа вже не отримає.
- Що ніхто не забрав, видаляється через 30 днів. TTL-політика Firestore на Spark **недоступна** (деплой відповідає «billing disabled»), тому раз на добу прострочене прибирають самі телефони учасників.
- Офлайн: невідправлене лишається в черзі й повторюється під час синхронізації (`SyncQueue`); те, що сервер не прийняв (завелике), повторно не женеться.

## Миттєві сповіщення (FCM + Supabase)

- Телефон кладе свій FCM-токен у `chats/{чат}/push/{uid}_{пристрій}` (читають лише учасники, пише лише власник).
- Після запису нагадування чи коментаря у спільний чат телефон кличе `https://lqspxwvyikuarfbfgnqf.supabase.co/functions/v1/notify` з Firebase ID token. Код функції — `supabase/functions/notify/index.ts`, таблиця ліміту — `supabase/migrations/`.
- Функція перевіряє підпис токена (JWKS securetoken), а чат і токени читає через Firestore REST **токеном самого користувача**, тож членство перевіряють правила. Далі шле іншим data-повідомлення FCM v1: нове нагадування чи коментар — HIGH, правка — HIGH, видалення — NORMAL. Ліміт — 30 сповіщень на хвилину від одного користувача (атомарно, у Postgres). Телефон-отримувач зливає сповіщення одного чату й синхронізує його не частіше за раз на 15 с.
- Безкоштовний проєкт Supabase засинає після тижня без запитів. Його тримає `.github/workflows/push-keepalive.yml` (GET раз на 3 дні). Якщо проєкт таки заснув: supabase.com → проєкт `nahadaika-push` → Restore. Поки він спить, працює запасна синхронізація раз на 2 години.
- Перевірка: `python tools/push_smoke_test.py`. Деплой функції — Supabase MCP або `npx supabase functions deploy notify --project-ref lqspxwvyikuarfbfgnqf`. У `supabase/config.toml` стоїть `verify_jwt = false`, бо функція сама перевіряє Firebase-токен.

## Кроки (один раз)

1. [console.firebase.google.com](https://console.firebase.google.com) → створити проєкт (Google Analytics не потрібен).
2. **Build → Authentication → Sign-in method** → увімкнути **Anonymous**.
3. **Build → Firestore Database** → Create database (режим production, регіон `eur3` або найближчий).
4. **Firestore → Rules** → вставити вміст [`firebase/firestore.rules`](../firebase/firestore.rules) → Publish.
5. **Project settings → General → Your apps** → додати Android-застосунок `ua.nahadaika`. Файл `google-services.json` не потрібен: з нього беруться три значення.
6. У `local.properties` (не комітиться) дописати:

   ```properties
   firebase.apiKey=AIza...            # "current_key" з google-services.json
   firebase.appId=1:1234567890:android:abc...   # "mobilesdk_app_id"
   firebase.projectId=nahadaika-xxxx  # "project_id"
   ```

   Для CI замість цього — секрети `FIREBASE_API_KEY`, `FIREBASE_APP_ID`, `FIREBASE_PROJECT_ID`.
   Google-вхід у CI потребує ще `FIREBASE_WEB_CLIENT_ID`; медіа — `FIREBASE_STORAGE_BUCKET`. Прив'язки додані у `.github/workflows/build.yml`; без значень функції залишаються вимкненими. Значення секретів GitHub під час локальної реалізації не змінювались.

7. Для синхронізації медіа (голосові, відео, фото) у спільних чатах:
   - **Build → Storage** → Create bucket (потребує плану Blaze у консолі Firebase; не вмикайте, якщо не плануєте платні сервіси).
   - **Storage → Rules** → вставити вміст [`firebase/storage.rules`](../firebase/storage.rules) → Publish.
   - У `local.properties` додати: `firebase.storageBucket=nahadaika-xxxx.firebasestorage.app` (або `gs://...`).
   - Якщо бакет не вказано, застосунок автоматично працює без вивантаження медіа: текст нагадувань синхронізується, а локальні записи не видаляються.

8. Для «Зберігати в хмарі» потрібен ще вхід через Google:
   - **Authentication → Sign-in method → Google** → увімкнути. **Web SDK configuration → Web client ID** записати в `local.properties` як `firebase.webClientId=…apps.googleusercontent.com`.
   - **Project settings → Your apps → ua.nahadaika → Add fingerprint** → додати обидва SHA-1:
     - релізний ключ: `1E:05:D4:AB:7E:E6:88:E3:01:3B:71:E1:0C:62:06:D2:B5:B0:E1:A1`
     - debug-ключ цього ПК: `FB:D9:F3:53:9F:24:7A:19:4A:72:14:73:18:B3:97:94:28:67:F6:6E`

   Якщо застосунок піде в Play з Play App Signing, додати й SHA-1 ключа Play (Play Console → Setup → App signing).

9. Зібрати `./gradlew assembleGithubRelease`.

## Як користуватися

Поточний стан реалізації, результати перевірок і межі готовності — у [SHARED_IMPLEMENTATION.md](SHARED_IMPLEMENTATION.md).

- Довге натискання на чат у списку (☰) → «Поділитися з рідними». Застосунок спитає ім'я, яке бачитимуть інші, і покаже код запрошення та кнопку «Надіслати».
- Учасник відкриває посилання `https://guns96x.github.io/nahadaika/?c=КОД` (сторінка `docs/index.html` на GitHub Pages відкриває застосунок через `nahadaika://join/КОД` або веде встановити APK) або у вікні «Новий чат» натискає «Маю код».
- Видалити спільний чат у себе означає вийти з нього. В інших учасників він лишається. Якщо ви були в ньому останнім (особистий чат у хмарі), він видаляється і з хмари.
- **Налаштування → Хмара → Зберігати в хмарі**: вхід через Google. Нові чати й перейменування теж ідуть у хмару. Вимкнення лише зупиняє вивантаження нових чатів; наявні копії лишаються.

## Безкоштовний план (Spark) — розрахунок

Ліміти Firestore на Spark: 1 ГіБ даних; на добу — 50 000 читань, 20 000 записів, 20 000 видалень; 10 ГіБ вихідного трафіку на місяць. Supabase Free: 500 тис. викликів функцій на місяць. FCM — безкоштовний.

Приклад: сім'я з 4 людей (3 отримувачі), спільний чат на ~150 документів. За день — 20 фото (~300 КБ, 1 шматок), 10 голосових (~240 КБ/хв, 1 шматок), 5 відео по 30 с (~6 МБ, 7 шматків) і 40 текстових змін.

| | на добу | ліміт |
|---|---|---|
| Записи (шматки + описи + нагадування + `receivedBy`) | ≈ 250 | 20 000 |
| Видалення доставленого | ≈ 100 | 20 000 |
| Читання медіа (кожен шматок + перевірка членства в правилах) | ≈ 800 | 50 000 |
| Читання синхронізації за push (весь чат × 3 отримувачі; без них, якщо застосунок відкритий) | до ≈ 18 000 | 50 000 |
| Запасна синхронізація раз на 2 год (весь чат × 4 телефони × 12) | ≈ 7 200 | 50 000 |
| Трафік медіа (38 МБ × 3 отримувачі) | ≈ 115 МБ (≈ 3,5 ГБ/міс) | 10 ГіБ/міс |
| Дані в хмарі | доставлене зникає за години; найгірше — ніхто не забирає 30 днів: ≈ 1,1 ГБ | 1 ГіБ |
| Виклики функції notify | ≈ 75 (≈ 2 300/міс) | 500 000/міс |

Тобто вкладаємося з запасом, крім двох крайніх випадків. Перший: дуже великі чати (тисячі документів), бо кожна синхронізація читає чат повністю. Ліки — інкрементальна синхронізація за `updatedAt`. Другий: учасник, який місяць не відкриває застосунок і не забирає відео. Тоді спрацює ліміт 1 ГіБ і нові медіа не вивантажаться, поки старі не прострочаться.

## Розумний час (Gemini)

Працює через той самий проєкт Firebase — окремого ключа Gemini в застосунку немає. У проєкті ввімкнено **Firebase AI Logic** (Gemini Developer API); застосунок шле запит на проксі `firebasevertexai.googleapis.com` з ключем Firebase. Модель задається в `app/build.gradle.kts` (`GEMINI_MODEL`, зараз `gemini-3.5-flash-lite`; 2.5 Flash-Lite для нових проєктів уже недоступна).

- **Голосове чи кружечок** → звук (з кружечка лише звукова доріжка; голосові пишуться 16 кГц моно 32 кбіт/с, ≈20 КБ на 5 с) → Gemini.
- **Текст** (надрукований або надиктований мікрофоном клавіатури) → кнопка ⏰ → у Gemini йде **лише текст**. Є час — нагадування ставиться саме; немає — вибір часу з уже очищеним текстом.
- Перед першим відправленням — згода; вимикається в налаштуваннях («Розумний час»).

Якість: `python tools/eval_gemini.py` (звук) і `python tools/eval_gemini.py --text` (текст) — 16 фраз українською, російською й англійською з еталоном. Останній прогін `gemini-3.5-flash-lite`: текст 16/16, звук 15/16, ≈2 с на запит.

Захист від зловживань:
- Застосунок шле `X-Android-Package` і `X-Android-Cert` (SHA-1 підпису, береться під час роботи). Ключ API обмежте в [Google Cloud → Credentials](https://console.cloud.google.com/apis/credentials/key/ec81d8e4-2788-47f2-bfca-51c982143333?project=nahadaika-89a9c) → Application restrictions → Android apps: `ua.nahadaika` + релізний SHA-1 і `ua.nahadaika` + debug SHA-1 (див. крок 8). Скрипти в `tools/` шлють ті самі заголовки з релізним SHA-1 (`firebase.certSha1` у `local.properties` — щоб змінити).
- З 2 листопада 2026 AI Logic вимагає **App Check**. Без нього розумний час перестане працювати — це окрема задача.
- Ліміт запитів на користувача: консоль Firebase → AI Logic → Settings.
